## 1. Product Overview

### Product Name
**VERIDACT**

### Tagline
**"See Through the Fake. Secure the Truth."**

### One-Line Pitch
VERIDACT is an AI-powered digital forensic evidence triage platform that helps Nepal Police Cyber Bureau investigators automatically detect deepfakes, voice clones, and synthetic media — generating SHA-256-hashed, timestamped forensic reports with full chain-of-custody logs.

### Problem Statement

Nepal Police Cyber Bureau receives a growing volume of cybercrime complaints each day. A significant and increasing proportion of these involve AI-generated or AI-manipulated digital evidence:

- **Deepfake images and videos** used to defame, harass, or fabricate evidence
- **Voice clone audio** used in scams, impersonation, and fraud
- **Synthetic identity documents** with forged metadata and altered content
- **Fake profile photos** generated by AI for social engineering
- **Tampered screenshots and documents** with invisible pixel-level manipulation

The Cyber Bureau faces three compounding challenges:

1. **Volume**: Manual review of every uploaded evidence file is unsustainable at scale.
2. **Technical Capacity**: Most investigators are not trained AI/ML specialists who can assess synthetic media.
3. **Legal Documentation**: There is no standardized tool to generate court-admissible forensic reports with proper file hashes, timestamps, and custody logs.

Investigators need a practical, fast, and trustworthy tool that helps them triage digital evidence, prioritize high-risk cases, and generate documented chain-of-custody records — without requiring AI expertise.

### Target Users

| User Group | Context | Need |
|---|---|---|
| Cyber Bureau Investigators | Daily case review | AI-assisted triage, case management, report generation |
| Department Supervisors | Case oversight | Case assignment, department analytics, review approvals |
| Cyber Bureau Super Admin | System management | User management, audit logs, system configuration |
| Citizens / Victims | Reporting complaints | Easy evidence submission, case tracking by ID |
| API Partners (Future) | Integration | Programmatic evidence submission and tracking |

### Hackathon Context

VERIDACT is being designed and prototyped as a **48-hour hackathon MVP** targeting:

- A realistic, functional localhost demonstration
- Clear problem-solution alignment
- Working AI evidence triage for image, video, audio, and document evidence
- Forensic PDF report generation
- Chain-of-custody logging
- Role-based access and dashboards
- Zero mandatory cost — all free, local, or open-source tools

The hackathon version is designed to demonstrate the concept, validate the user flows, and present a credible technical architecture — not to serve as production-ready software.

### Localhost MVP Scope

The MVP will:
- Run fully on `localhost` — no cloud, no domain, no paid hosting required
- Use SQLite as the local database
- Store uploaded files in `/uploads/` on the local filesystem
- Run AI inference locally using free Hugging Face models or lightweight fallbacks
- Generate PDF reports using Python-based free libraries (ReportLab)
- Use JWT-based authentication with demo seed users

### Why This Project Matters

AI-generated fake evidence is not a future risk — it is happening today. In countries like Nepal, where legal and forensic infrastructure is still developing, investigators are particularly vulnerable to being overwhelmed or misled by synthetic media. VERIDACT represents a category of tool that every country's cybercrime unit will eventually need. Building it as open-source, localhost-first, zero-cost infrastructure means it could be deployed even in resource-constrained environments. This is not just a hackathon project — it is a blueprint for democratizing forensic AI tooling.

## 2. Goals

### Primary Goal
Build a working, demo-ready AI forensic evidence platform that can run entirely on localhost, allowing investigators to upload digital evidence, receive AI-powered analysis with confidence scores, and download a professional forensic PDF report — all within a single browser session.

### Secondary Goals
- Create a complete case management workflow from citizen complaint submission to report generation
- Implement SHA-256 hash-based file integrity verification
- Build a chain-of-custody logging system that captures every significant evidence action
- Provide role-based access for super admins, supervisors, investigators, and citizens
- Show a working citizen case tracking flow using a case number

### Demo Goal
By the end of the hackathon, present a live, uninterrupted 5-minute demo that flows through:
1. A citizen submitting a suspicious image or video as a complaint
2. The system generating a case ID and SHA-256 hash
3. An investigator logging in and reviewing the case
4. The AI analysis returning a confidence score and verdict
5. The investigator generating and downloading a forensic PDF report
6. The chain-of-custody log showing every action taken

### Technical Goal
- Implement a modular AI inference pipeline that routes evidence by file type and can swap models without changing the API contract
- Ensure the backend is stateless and the database schema is normalized enough to migrate to PostgreSQL with no logic changes
- Achieve sub-5-second analysis time for images (on a modern laptop without GPU)

### AI/ML Goal
- Correctly route image, video, audio, and document evidence to appropriate analysis modules
- Return a normalized verdict (Authentic / Suspicious / Likely Fake / Inconclusive) for all evidence types
- Gracefully degrade to a safe demo fallback when a heavy model cannot run in the demo environment

### User Experience Goal
- A citizen with no technical knowledge should be able to submit evidence in under 3 minutes
- An investigator should be able to see a full case view, trigger analysis, and generate a report in under 10 minutes
- All AI results should include a human-readable explanation, not just a number

### Social Impact Goal
Demonstrate that AI forensic tooling for cybercrime can be built as open-source, free, and locally deployable infrastructure — accessible to law enforcement agencies in developing countries that cannot afford enterprise solutions.

## 3. Non-Goals

The following will **not** be built or claimed in the hackathon MVP. This is important for honest scoping, judge communication, and team focus.

| Non-Goal | Reason |
|---|---|
| **No paid hosting requirement** | All services run on localhost; no Vercel, Render, AWS, or paid cloud required |
| **No paid domain** | The demo uses `localhost:3000` and `localhost:8000`; no domain purchase needed |
| **No mandatory paid AI API** | OpenAI, paid Hugging Face Inference, Replicate, or similar paid APIs are not required |
| **No blockchain custody log** | Blockchain immutability is a future enhancement; SQLite timestamped logs are sufficient for MVP |
| **No enterprise deployment** | No Kubernetes, Docker Swarm, load balancing, or production infrastructure required |
| **No production Nepal Police integration** | VERIDACT is a standalone prototype, not integrated into Nepal Police's systems |
| **No mobile application** | The MVP is a web application only; no React Native or mobile-first implementation |
| **No real criminal database integration** | No connection to INTERPOL, national ID databases, or criminal records |
| **No batch processing queue** | Celery, Redis, or background job queues are future scope; MVP uses synchronous analysis |
| **No federated learning** | Model training and privacy-preserving ML are future research scope |
| **No multilingual support** | English-first MVP; Nepali language support is future scope |
| **No SMS/email notifications** | Notification services are future scope |
| **No claim of replacing human forensic experts** | VERIDACT is explicitly an AI-assisted triage tool; human expert review is always required |
| **No guarantees of forensic accuracy** | AI confidence scores are probabilistic; they are not legal conclusions |
| **No API partner implementation** | The API partner role is documented but not fully implemented in MVP |

## 5. Core Features

### Feature F-01: Authentication and RBAC

**Feature ID:** F-01
**Feature Name:** Authentication and Role-Based Access Control
**Description:** Secure login and registration with JWT tokens and role-based route protection. Different users see different dashboards and capabilities based on their role.
**User Story:** As an investigator, I need to log in with my credentials so that I can access only the cases assigned to me and not see sensitive admin data.
**Priority:** Must Have
**Input:** Email, password
**Output:** JWT token, role-scoped dashboard redirect
**AI/Model Involvement:** None
**Database Involvement:** `users` table — read (login), write (register)
**Acceptance Criteria:**
- Login with valid credentials returns a JWT token
- Invalid credentials return a 401 error with a clear message
- JWT tokens expire after 8 hours
- Protected routes reject requests without a valid token
- Each role sees only the pages and data they are authorized for
- Demo seed users for all 4 roles work on first startup

---

### Feature F-02: Citizen Evidence Submission

**Feature ID:** F-02
**Feature Name:** Citizen Evidence Submission Wizard
**Description:** A 4-step guided form allowing citizens to submit cybercrime complaints with digital evidence. The system generates a unique case number, SHA-256 hash, and an acknowledgment PDF.
**User Story:** As a citizen, I want to report a suspected deepfake image used to defame me, upload the file, and receive a case number so I can track my complaint.
**Priority:** Must Have
**Input:** Complaint type, title, description, contact details, optional location, evidence file
**Output:** Case ID (format: VRD-YYYY-NNNNNN), SHA-256 hash of uploaded file, timestamped acknowledgment PDF
**AI/Model Involvement:** None at submission stage (analysis is triggered later by investigator)
**Database Involvement:** `cases` table (write), `evidence` table (write), `custody_logs` table (write)
**Acceptance Criteria:**
- Citizen can complete the wizard in 4 steps without login
- File upload accepts image, video, audio, and document types
- SHA-256 hash is computed server-side immediately on upload
- Case number is generated with format VRD-YYYY-NNNNNN
- Custody log entry is created for `case_created` and `evidence_uploaded`
- Citizen receives a confirmation screen with case number and hash
- Acknowledgment PDF can be downloaded from the confirmation screen

### Feature F-03: Case Management

**Feature ID:** F-03
**Feature Name:** Case Management Dashboard
**Description:** A filterable, searchable case list with full case detail views. Investigators see only assigned cases; supervisors see their department; super admins see all.
**User Story:** As an investigator, I want to see all my assigned cases sorted by priority, so I can triage and work on the most urgent cases first.
**Priority:** Must Have
**Input:** Role-based case query, filters (status, type, priority, date range), search term
**Output:** Paginated case list, case detail view with all linked evidence and notes
**AI/Model Involvement:** None (displays AI results that were already computed)
**Database Involvement:** `cases`, `evidence`, `case_notes`, `analysis_results`, `custody_logs` — read
**Acceptance Criteria:**
- Investigator dashboard shows only cases where `assigned_to = current_user.id`
- Case list is sortable by status, priority, and created_at
- Filtering by status and complaint_type works
- Opening a case shows case details, all evidence items, all notes, and status history
- Supervisor can reassign a case to a different investigator
- Status can be updated from the case detail page with a reason
- Custody log entry is written on every status update

### Feature F-04: Evidence Upload and Storage

**Feature ID:** F-04
**Feature Name:** Evidence Upload and Local Storage
**Description:** Secure file upload with MIME type validation, SHA-256 hash generation, local filesystem storage, and evidence metadata persistence.
**User Story:** As an investigator, I want to upload additional evidence files to an existing case and have the system compute their hash and store them securely.
**Priority:** Must Have
**Input:** File (image/video/audio/document), case ID, uploader ID
**Output:** Evidence record in database, file stored in `/uploads/evidence/`, SHA-256 hash, custody log entry
**AI/Model Involvement:** None at upload stage
**Database Involvement:** `evidence` table (write), `custody_logs` table (write)
**Acceptance Criteria:**
- Supported types: `.jpg`, `.jpeg`, `.png`, `.gif`, `.bmp`, `.webp`, `.mp4`, `.avi`, `.mov`, `.mkv`, `.mp3`, `.wav`, `.aac`, `.ogg`, `.flac`, `.pdf`, `.docx`, `.xlsx`, `.txt`
- Maximum file size: 100MB per file (configurable via `.env`)
- Stored filename uses UUID to prevent collisions and directory traversal
- SHA-256 hash is computed server-side and stored in `evidence.sha256_hash`
- Upload status is set to `uploaded` immediately; `processing` during analysis
- A custody log event `evidence_uploaded` is created with IP address
- Files are never served directly from a path that reveals internal structure

### Feature F-05: AI Evidence Analysis

**Feature ID:** F-05
**Feature Name:** AI-Powered Evidence Analysis
**Description:** An AI inference pipeline that routes evidence by file type to specialized detectors, returns a confidence score and verdict, and stores the result for report generation.
**User Story:** As an investigator, I want to click "Analyze Evidence" on an uploaded file and receive an AI-generated verdict with a confidence score so I can prioritize it.
**Priority:** Must Have
**Input:** Evidence ID, file type
**Output:** Confidence score (0.0–1.0), verdict (Authentic/Suspicious/Likely Fake/Inconclusive), explanation text, optional heatmap image path
**AI/Model Involvement:** See Section 7 for detailed AI model blueprint
**Database Involvement:** `analysis_results` table (write), `custody_logs` table (write)
**Acceptance Criteria:**
- Clicking "Analyze" triggers a POST to `/api/evidence/{evidence_id}/analyze`
- File type is detected from MIME type, not just extension
- Image analysis returns within 30 seconds on a modern laptop
- Video analysis samples at most 10 frames and returns within 60 seconds
- Audio analysis returns within 30 seconds (or demo fallback is used)
- Document analysis returns within 15 seconds
- All results include explanation text (not just a number)
- If a model fails, a safe fallback result is returned with `model_used: "fallback_demo"`
- Processing status is updated: `pending` → `processing` → `completed` or `failed`
- Custody log event `analysis_started` and `analysis_completed` are written

### Feature F-06: Chain of Custody

**Feature ID:** F-06
**Feature Name:** Chain-of-Custody Logging
**Description:** An immutable (append-only by design) audit trail logging every significant action performed on a case or evidence item. Each log entry captures who did what, when, and from where.
**User Story:** As a supervisor, I want to see a complete timeline of every action taken on a case — who uploaded evidence, when analysis was run, and who generated the report — for court documentation purposes.
**Priority:** Must Have
**Input:** Action event (triggered automatically by every major system operation)
**Output:** Custody log entry with user, case, evidence, action, IP, timestamp
**AI/Model Involvement:** None
**Database Involvement:** `custody_logs` table (write on every action, read on audit view)
**Acceptance Criteria:**
- Custody log is written automatically for: `case_created`, `evidence_uploaded`, `evidence_accessed`, `analysis_started`, `analysis_completed`, `report_generated`, `case_updated`, `file_downloaded`, `case_closed`
- No log entry can be modified or deleted (append-only enforced at service layer)
- The custody log viewer shows logs in chronological order with actor, action, and timestamp
- IP address is captured where available
- Admin can view custody logs for any case via `/admin/custody`
- Each case's custody log is included in the forensic PDF report

### Feature F-07: Forensic Report Generation

**Feature ID:** F-07
**Feature Name:** Forensic PDF Report Generation
**Description:** Generate a professional, court-style forensic PDF report for a case, including evidence metadata, SHA-256 hash, AI analysis results, chain-of-custody summary, and an explicit AI disclaimer.
**User Story:** As an investigator, I want to generate a single PDF report for a case that contains all the evidence, AI analysis results, and custody log so I can submit it for review.
**Priority:** Must Have
**Input:** Case ID (all linked evidence, analysis results, custody logs, and notes are pulled automatically)
**Output:** Downloadable PDF file with all forensic details, stored in `/uploads/reports/` with its own SHA-256 hash
**AI/Model Involvement:** Template-based PDF (ReportLab); optional LLM narrative generation (Gemini free tier — optional only)
**Database Involvement:** `reports` table (write), `custody_logs` table (write for `report_generated`)
**Acceptance Criteria:**
- PDF contains: case number, case title, complaint type, status, submitted by, assigned to, submission timestamp

- Report can be downloaded from the case detail page and the `/dashboard/reports` list

## 7. AI Features

### AI Feature A-01: Image Deepfake Detection

**What the AI Does:** Analyzes an uploaded image to determine if it is likely AI-generated, GAN-synthesized, or manipulated using deepfake techniques. Returns a confidence score and verdict.

**Recommended Free Pretrained Model:**
- Primary: `prithivMLmods/Deepfake-Detect-Siglip2` (Hugging Face)
- Fallback: `Wvolf/ViT_Deepfake_Detection` (Hugging Face)
- Both are free, downloadable, and can run locally via `transformers` library

**Runs Locally:** Yes — both models can be loaded via `AutoModelForImageClassification` from Hugging Face. They require ~1–2GB RAM and run on CPU (slower, ~5–15s per image) or GPU (faster, ~1–2s).

**Input Format:** PIL Image or JPEG/PNG file path

**Output Format:**
```json
{
  "confidence_score": 0.87,
  "verdict": "likely_fake",
  "label": "FAKE",
  "explanation": "High confidence of AI-generated facial features detected. Model: SigLIP2-based deepfake classifier.",
  "model_used": "prithivMLmods/Deepfake-Detect-Siglip2",
  "model_version": "1.0"
}
```

**Failure Fallback:** If the model fails to load (OOM, missing weights), the system falls back to a deterministic hash-based mock that assigns `inconclusive` with explanation "Model unavailable in current environment. Manual review required."

**Non-AI Fallback for Demo Safety:** A `DEMO_MODE=true` flag in `.env` enables a pre-scripted response based on file hash prefix — sample files in `demo_assets/` will always return expected results regardless of model availability.

---

### AI Feature A-02: Video Deepfake Detection

**What the AI Does:** Extracts up to 10 evenly-spaced frames from an uploaded video using OpenCV, runs each frame through the image deepfake detector, and aggregates scores to produce a final verdict.

**Model:** Same image classifier as A-01, applied frame-by-frame. No separate video model needed.

**Runs Locally:** Yes — OpenCV frame extraction is local; image detector is the same as A-01.

**Input Format:** Video file path (`.mp4`, `.avi`, `.mov`, `.mkv`)

**Output Format:**
```json
{
  "confidence_score": 0.74,
  "verdict": "suspicious",
  "frames_analyzed": 10,
  "frame_scores": [0.71, 0.68, 0.79, 0.83, ...],
  "explanation": "7 of 10 analyzed frames show suspicious AI-generation artifacts.",
  "model_used": "frame_sampling + prithivMLmods/Deepfake-Detect-Siglip2"
}
```

**Failure Fallback:** If frame extraction fails (codec issue), returns `inconclusive` with note on codec.

### AI Feature A-03: Audio Voice Clone Detection

**What the AI Does:** Analyzes audio for signs of voice cloning or synthetic speech. Uses spectrogram feature extraction as primary signal.

**Recommended Free Model:**
- Primary: `facebook/wav2vec2-base` fine-tuned on spoofing detection (if available on HF)
- Alternative: `microsoft/wavlm-base` with spoofing adaptation
- Both are heavy locally (~300MB–700MB). Use fallback for demo if load time is prohibitive.

**Fallback (MVP Recommended):** Extract MFCC features with `librosa`, check for suspicious uniformity patterns in formants, and return a heuristic score. This is not as accurate as a trained model but is fast and reliable for demo.

**Runs Locally:** Heuristic fallback — yes. Full wav2vec2 — yes but slow (~30s on CPU for 10s audio clip).

**Input Format:** Audio file (`.mp3`, `.wav`, `.aac`, `.ogg`, `.flac`)

**Output Format:**
```json
{
  "confidence_score": 0.61,
  "verdict": "suspicious",
  "explanation": "Spectral uniformity analysis detected possible voice synthesis artifacts. Manual audio forensics recommended.",
  "model_used": "librosa_heuristic_fallback",
  "duration_seconds": 12.4
}
```

### AI Feature A-04: Document Forgery Detection

**What the AI Does:** Extracts file metadata, runs Tesseract OCR, checks for suspicious metadata mismatches (creation date after modification date, software field indicating AI tools, GPS data inconsistencies), and applies ELA-style checks for images embedded in documents.

**Tools Used:**
- `pytesseract` + `tesseract-ocr` (system dependency): Free, fully local
- `python-magic` or `mimetypes`: MIME type validation
- `pikepdf` / `PyMuPDF` for PDF metadata extraction
- `Pillow` for ELA (Error Level Analysis) on embedded images
- `python-docx` for DOCX metadata

**Runs Locally:** Yes — all libraries are free and local.

**Input Format:** Document file (`.pdf`, `.docx`, `.xlsx`, `.txt`, `.jpg` used as document evidence)

**Output Format:**

## 8. Forensic and Legal Positioning

VERIDACT is an **AI-assisted forensic triage tool**, not a forensic authority. This distinction is critical for ethical deployment and legal defensibility.

### What VERIDACT Claims to Do

- **Triage assistance:** Help investigators quickly identify which evidence warrants closer human expert examination
- **File integrity:** SHA-256 hashing proves that a file has not been modified since submission to the platform
- **Custody documentation:** Timestamped logs create an auditable record of who handled evidence and when
- **Preliminary scoring:** Confidence scores and verdicts represent the output of statistical ML models, not legal conclusions
- **Report generation:** PDF reports organize evidence metadata and AI findings in a structured format suitable for human review

### What VERIDACT Does Not Claim

- VERIDACT **does not** certify that any file is definitively real or definitively fake
- VERIDACT **does not** replace a qualified digital forensic examiner's analysis
- VERIDACT **does not** produce legally binding evidence in isolation
- VERIDACT **does not** guarantee zero false positives or zero false negatives
- VERIDACT AI confidence scores **must** be reviewed and validated by a human expert before use in any legal proceeding

### Every Report Contains the Following Disclaimer

> *"This report was generated using VERIDACT AI-assisted triage tools. AI analysis results (confidence scores and verdicts) are probabilistic in nature and are intended to assist investigators in prioritizing evidence review — not to serve as definitive forensic conclusions. All findings must be reviewed and verified by a qualified human digital forensic expert before use in any investigation, prosecution, or legal proceeding. The SHA-256 file hash provides file integrity verification from the time of upload but does not independently establish the provenance or authenticity of the original file."*

### Chain of Custody Positioning

VERIDACT's custody logs provide:
- **Who** uploaded or accessed evidence (authenticated user ID)
- **What** action was taken
- **When** it happened (UTC timestamp, server-side)
- **From where** (IP address where available)

This is not blockchain-level immutability in the MVP (that is future scope), but it provides a documented audit trail that can support an investigator's testimony about the handling of digital evidence.

## 10. Risks and Mitigation

### Technical Risks

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| AI model too heavy for demo laptop | Medium | High | Pre-download models; use lightweight fallback; DEMO_MODE flag |
| SQLite locking under concurrent requests | Low | Medium | Use WAL mode; hackathon has low concurrency |
| PDF generation fails | Low | High | Pre-generate sample PDF; store in demo_assets |
| Video codec not supported by OpenCV | Medium | Medium | Use MP4 only for demo; document supported types clearly |
| File upload path traversal exploit | Low | Critical | UUID-based stored filenames; no path in response |

### AI/Model Risks

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| False positive on real image | High | Medium | Disclaimer on every result; never present as definitive |
| False negative on real deepfake | High | Medium | Same disclaimer; triage tool framing |
| Model download fails during demo | Medium | High | Pre-download all models to local cache; use HF_HUB_OFFLINE=1 |
| Hugging Face model changes API | Low | Medium | Pin exact model version and commit hash |

### Data Risks

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Demo uses real sensitive faces | Medium | High | Use only synthetic/public domain faces in demo_assets |
| SQLite DB file corrupted | Low | High | Include pre-seeded backup DB in repo |
| Evidence file accidentally exposed | Low | Critical | Serve files via authenticated endpoint only, never directly from /uploads |

### Time Risks

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| AI analysis takes too long to implement | Medium | High | Implement image analysis first; mock video/audio if needed |
| PDF generation takes too long | Low | Medium | ReportLab is fast; implement in Phase 6 with ReportLab template |
| Team merge conflicts | Medium | Medium | See No Merge Conflict Strategy below |
| Feature scope creep | High | High | Stick strictly to MVP feature list; defer nice-to-haves |

### Demo Risks

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Demo laptop has no internet | Medium | Medium | Pre-download models; HF_HUB_OFFLINE=1; no external dependencies |
| AI model crashes mid-demo | Medium | High | Demo seed data has pre-computed results stored in DB |
| Backend fails to start | Low | Critical | Keep .env pre-configured; test startup on demo device the night before |

### Privacy Risks

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Demo files contain real faces | Medium | High | Use only synthetic AI-generated faces (from thispersondoesnotexist.com or similar) for demo |
| User passwords stored insecurely | Low | Critical | bcrypt hashing; no plaintext anywhere |

### False Positive / False Negative Risks

| Risk | Mitigation |
|---|---|
| AI marks real image as deepfake | Prominent disclaimer; confidence score shown; "AI-assisted triage only" framing |
| AI misses a real deepfake | Same disclaimer; system is explicitly a first-pass triage tool, not a ground truth |
| Judges think AI is 100% accurate | Proactively explain probabilistic nature during demo; quote confidence score thresholds |
